# Connected inventory workspace

Entry: `/admin/inventory/manage` (Inventory in the admin sidebar). Daily stock routines remain at `/admin/inventory/check`, including Work task links, phone category selector, Recheck tomorrow, custom units, and saved history. Existing counts and order requests require no migration. Legacy supplier/location/item tools remain at `/admin/inventory` through How stock works.

## Operational flow

1. **Overview:** search or filter goods, see last known stock and count freshness, and record a quick physical count. Add or edit goods, storage locations, categories and default counting units. A change to item metadata never converts existing stock.
2. **Directory:** add/edit suppliers and associate any good with multiple supplier products. Record exact supplier wording, SKU, package contents quantity/unit, ordering unit and preferred source. A case containing 40 lb is explicit; the app never assumes all cases contain the same amount.
3. **Orders:** build supplier-specific lists without an on-hand count. Daily requests prefill only when ordering units match. Copy supplier product names/SKUs and buy quantities. Record an order only after placing it outside TableGo; recording or copying does not contact a supplier or buy goods. Historical order lines preserve the names/package sizes used when placed.
4. **Receiving:** record delivered and damaged quantities, optional receiver name and discrepancy notes. Partial deliveries remain open. Damage is part of delivered quantity and retained for invoice reconciliation. Deliveries record arrival and purchase history only; they never replenish or modify on-hand stock, regardless of package units. Daily internal requests are not silently canceled by recording a supplier order.
5. **Invoices:** photograph/upload an invoice page or PDF. Photos are resized copies; PDFs are retained as uploaded, maximum 3 MB per attachment. Photo OCR runs on the device; worker/language assets download from the OCR library's public hosts, but invoice images are not sent to an OCR service. PDFs support upload plus manual/pasted entry. Review suggested invoice number/date/total and line descriptions, quantities and explicit currency prices. Match supplier/order/items; save draft or reviewed. Invoice entry never changes stock.

## Accuracy and accountability

On-hand stock comes only from confirmed physical counts. Usage/waste is not automatically deducted. Earlier delivery estimates, if present in stored history, are excluded from the displayed physical count and require a recount; historical records are not rewritten. Recheck tomorrow records a sufficient-stock review without pretending that an older quantity was recounted.

Orders, counts, receiving and edits produce authenticated audit records. Optional staff labels supplement the actual staff session actor; shared PIN sessions identify the session, not an independently verified employee identity. Reconciliation flags quantity/unit mismatches, unmatched/missing order items, duplicate-line aggregate quantities, arithmetic/total differences and damaged-delivery credit/replacement concerns. Warnings are for human review; tax, freight, discounts and partial invoicing may explain differences. Invoice price history labels drafts separately.

New operations live under server-only `inventoryOperations/*/records/*`. Existing `inventory/current` remains authoritative for stock. Attachments are immutable, authenticated, signature/MIME-validated private Firestore chunks with bounded upload bodies and no public URLs. Original full audit events remain stored. Latest history has paginated older reads; catalog and mapping limits are explicit. No deletion tools, automated purchasing, supplier messages, payments, financial-account integration or accounting exports are introduced.

Counts and receipts use Firestore transactions, explicit item versions where appropriate, and durable request keys so repeated submissions cannot duplicate their records. Receiving never writes on-hand inventory. The UI retains the identical payload/key when a response is uncertain and asks staff to reconcile saved records before entering a replacement. Form close asks before discarding; uploads/unused private attachments remain retained. Invoice forms require Use invoice details after capture before Save becomes available.

## Voice/text stock log — October 28, 2026

Overview offers **Speak or type stock log**. On iPhone, focus the large text box and use the keyboard microphone, finish dictation, then **Review log**. Logs support up to 200 reviewed entries at once, covering the current catalog. Native keyboard dictation avoids a separate website microphone permission. Typed text works on other devices. Text drafts stay on the device under the restaurant date. The local parser supports item-first/quantity-first phrases, ordinary continuous lists, spoken numbers/fractions, common units, and exact supplier aliases. Unknown products, missing quantities, ambiguous variants, duplicate items and unclear units remain visible for correction; they are never silently discarded or saved as zero.

Review matches, quantities and units, compare against the last physical counts, acknowledge changed units, then explicitly confirm the whole check. Server confirmation validates every current item version and the restaurant date in one transaction. Any invalid/stale line prevents every count from being saved. The original text, actor/time and per-item before/after history are retained privately. Interrupted retries retain the original request ID and payload. Counts update the same stock records used by Daily stock check and Work.

Reviewed invoices can explicitly add unmatched products and exact supplier mappings to the catalog (category defaults to Unsorted goods). This creates no on-hand record. Drafts keep that intent without creating goods; ambiguous matches must be resolved. Overview exposes last ordered/arrival/invoiced history when known, separately from stock.

Verification includes parser, UI and atomic repository tests plus a staging lifecycle proving receiving leaves stock byte-for-byte unchanged, confirmation is atomic and retry-safe, and reviewed invoice catalog creation never creates or changes stock quantities.

Stock-log release verification: 336 full-suite tests passed, together with typecheck, lint, production build, actual staging transaction tests, and a phone-size browser log review/confirmation. The staging API additionally verified the deployed confirmation handler rejects invalid logs without changing stock.
